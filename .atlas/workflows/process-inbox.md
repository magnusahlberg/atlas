# process-inbox

Walk through `Inbox.md` and sort each item into the right list.

---

Walk through every item in `Inbox.md`. For each item, ask:

1. Is it actionable?
2. If not actionable: park in Someday Maybe.md, file as Reference, or delete.
3. If actionable and < 2 min: do it now (or with me), then archive.
4. If actionable and multi-step: create a project in Projects.md, identify next action, add to Next Actions.md with context tag.
5. If actionable and single-step: add to Next Actions.md with context tag.
6. If waiting on someone: add to Waiting For.md with who and follow-up date.

Propose every move before making it. Use wikilinks to connect actions to projects to goals. Use context headings @deep-work, @call, @meeting, @computer.

Two conventions to apply as you file:

- **`[for:: Full Name]`** on every `@meeting` item. These are still my actions; the person is the context, not the owner. If the work is genuinely theirs, it belongs in `Waiting For.md` instead.
- **`[src:: ...]`** carried forward. If an inbox item already has a source link, keep it on the filed line. Never drop it.

After processing, Inbox.md should be empty (or contain only items I explicitly chose to defer with a reason).

When presenting items for review, number them so I can respond by number.
